# 当前会话历史插件 0.1.0：本轮对照结论

状态：本轮 V7 与 V8.1 插件对照均已运行并复核。插件保持 0.1.0，不追溯修改工具或成绩。复核为 AI 非盲复核，不是独立人工盲评。以下是单案例材料、单模型路由下的探索性结果。

## 固定条件与证据

- DSH 0.2.2-rc.3，Web-host 运行时，无桌面窗口；provider 为 deepseek-official，model 为 deepseek-flash，effort 为 low。
- 每套用例三组新会话，每组从同一检查点克隆 A、A_repeat、B；只有 B 压缩。
- 插件只在 recovery 加载。prefix、compact、recall 均不加载，不能用闭卷成绩变化证明插件效果。
- 插件 index.cjs SHA-256：`59f9d2dc76db003b7a13573d9072518e980de69cb44f387224b84a62773f5fb3`。
- V7 案例哈希：`8a4a7cf1b400a731c818b8d2e144e494c9ad121ef3d7456990b1d40dd41abf58`。
- V8.1 案例哈希：`5946d350678d1c6e1d8f47ef6c98e9f874bdffc2ae34cb2f48f98d51bf1ac42d`。
- V8.1 receipt 校验器修订为 labelled-receipt-line-v1.1，修复正文“不引用任何文件”误触发引用块；基线与插件版共36次回答均复检通过。语义验收要求不变。

逐项评分、原始事件及完整报告位于本地 studies/，按项目规则不随源码上传。V7 插件记录为 v7-plugin-1/2/3，基线为 detail-v7-2/3/4；V8.1 插件记录为 task-v8_1-plugin-1/2/3，基线为 task-v8_1-1/2/3。最终复核口径以另存的 task-v8_1-review 和 task-v8_1-plugin-review 为准，不能用旧版基线全满分汇总替代复核结果。

三组 V8.1 的压缩证据覆盖 seed-1、seed-2、seed-3，声明的 receipt 锚点覆盖1/1；10项验收条件另行评分。三组均已生成 scores-reviewed.json、report.json、report.html，评分绑定运行、案例与回答快照。

### V7：一项真实错码，一次格式失败

第3组 B/recovery 将 QL-0007 写成相邻工单的回执码。搜索返回的片段在目标工单之前包含另一条记录的码，模型没有再读取完整事件，最终输出错误配对。这是需要保留的真实失败，不能因检索变快而忽略。

第1组 A_repeat/recovery 的表格包含10个正确配对，但未满足旧V7逐行配对校验。按冻结规则记10项 unknown，内容诊断仍为10/10；不能将其解释为遗忘，也不能临时放宽规则制造满分。

插件实际调用85次：84次 search、1次 read。多数回答依靠搜索片段，未稳定使用 read。

### V8.1：查回交付全过，闭卷仍有权限表述错误

唯一完整交付失败为第2组 B/recall：将“审批权限未说明”写成各审批人“均未指定”，authority 与全文无编造事实的 delivery 条件均判 wrong。此时插件尚未加载，不能归因于插件。

第1组 B/recovery 的 search 返回 seq9/28/40 三条完整原文，均标为未截断，与原始文本一致；因此“完整读取”的声明可以成立，不要求必须调用名为 read 的工具。先前错误降级已撤销，并保留旧版复核。

插件实际调用60次：42次 search、18次 read；7/9次 recovery 出现 read 调用。一次 read(seq0)失败仍保留在工具次数中。

## 能支持的结论

本次插件组的查回耗时与工具次数均低于历史基线；这是观察到的效率变化，尚不能认定为稳定的因果收益。没有采集 token、费用、缓存命中或首字延迟，不能据此宣称更省钱或缓存更好。

V8.1 recovery 从8次通过、1次待定变为9次通过，基线待定不等于确定失败。不同运行的生成历史存在差异，且没有同期随机分配的无插件对照，尚不能区分插件贡献与运行波动。整体14→17不能全部归因于只在recovery加载的插件。

V7 暴露了搜索片段的相邻信息混淆风险。V8.1 的单条独立凭据没有复现该问题，不代表风险已经解决。

## 下一版优先范围

优先处理搜索结果的相邻记录边界：明确标出实际命中范围，将目标记录与前后文分开，避免无所属标识的相邻码出现在同一展示片段。截断时明确引导读取对应事件及偏移，不强制所有命中都额外调用read。

保留当前0.1.0文件及实验快照，新实现使用新插件版本。先用不含正式标准答案的合成邻接记录验证片段与来源对应、截断及分页，再重跑冻结V7/V8.1。不得用针对QL编号或已知码值的特殊解析来提高成绩。

更广泛的成功率结论还需要新场景、新材料及同期交错运行的对照；应在实验前定义条件，避免根据结果调整评分。闭卷状态保留、权限未知表述和缓存优化不纳入本轮查回插件的效果声明。
