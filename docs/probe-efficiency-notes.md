# 细节探针修订记录

旧 v6 使用按编号循环的工单主题，不能有效区分早期记忆与规律推算。复核时仅使用最后一批建立余数映射，即可还原全部十项主题。这使得“摘要没保留该主题”与“模型能否答题”不能直接对应。旧方案已退役，原始案例与已有运行记录保留，不能继续拿来支持压缩遗忘结论。

修订后的 v7 改用工单独有的回执码：HMAC 的私有种子仅存于操作员材料，单条提示只含该工单自身的值。相同种子可复现材料，换种子会改变答案；末尾负载不提供早期答案，也不提供能推算它们的周期规律。

运行器通过 `probe_anchors` 校验原始工单覆盖与真实入场，通过压缩事件记录实际替代范围，并按 `allowed_grades` 验证三档评分。不以增加负载数量替代探针有效性检查。

具体材料见 [v7 案例](../cases/long-context-compaction-qinglu-v7.json)，执行见[自动运行说明](long-context-runner.md)。尚无 v7 模型实测成绩。
