# V9：陌生材料与同期交错对照

目标是检查历史查回插件能否处理不同于青鹭案例的材料，尤其是跨行字段、同一行多个对象、重复命中和旧版本替代。V9不是V7/V8.1分数的延伸；不改旧材料、旧评分或插件文件。

## 冻结材料

场景为虚构的“岚桥设备维保交接”。cases/transfer-v9/case-1.json、case-2.json、case-3.json分别保存不同编号、码值、预算和日期，使用操作员侧私有种子复现。种子、预期答案、评分和未来问题不得交给目标。

每份包括3轮项目消息、12批共384条巡检负载，以及10个正式回执。负载含干扰与作废码，不可采用。布局覆盖：

| 锚点 | 场景 |
|---|---|
| f1 | 编号与回执跨行 |
| f2 | 同一行三个对象，各有码值 |
| f3 | 旧版作废，后续明确正式替代 |
| f4 | 长行超过片段限额，码在远端 |
| f5 | 超过10条原始用户消息重复命中同一编号，最终正式版本在第12批 |
| f6 | Unicode编号与相似ASCII编号 |
| f7 | JSON字段 |
| f8 | Markdown表格 |
| f9 | 大写回执原文 |
| f10 | 空行分隔的多字段签收单 |

原始来源用source_quote逐字绑定源轮次，并由运行器核对已冻结输入；真实运行还需核对原始消息实际入场及压缩替代证据。这里不声称程序能从复杂布局自动证明语义归属，最终评分须对照对象、签收状态与版本。

另有state、authority、delivery三项，合计13项验收、3个子任务。完整交付要求13项全correct，不给部分分。预算、人员、日期、核验前置条件、未知权限及正式固定句都来自新场景。交接结论最多180非空白字符，需人工确定正文范围后核对；程序不自动完成这些语义审阅。

此版固定12批，不追加负载；改变材料或负载时另建版本。如果原生压缩未覆盖目标来源、提前自动压缩或闭卷调用工具，保留失败证据，不补造有效对照。

## 准备与执行

先阅读[完整测试流程](plugin-test-workflow.md)，在同一终端准备认证。下面prepare只创建六个新计划与插件快照，不调用模型：

```sh
python3 transfercase.py prepare --output studies/transfer-v9-paired-1
```

同一材料分配给0.1.0和0.1.1，各三组，顺序写入schedule.json。三个材料块的顺序和先执行的版本按固定seed打乱；两块旧版先、一块新版先，交错次序在看结果前冻结。不是完全均衡或大样本随机实验。

确认计划无误后，在配置好模型认证的终端执行：

```sh
python3 transfercase.py run --schedule studies/transfer-v9-paired-1/schedule.json
```

命令会按冻结顺序调用真实模型，顺次完成六组。每组仍为A/A_repeat/B三分支，仅B压缩，插件只在recovery加载。每个版本之间是独立会话，助手前缀历史可能不同；“成对”指输入材料相同，不冒充跨版本共享检查点。

全部任务的运行器源码、冻结配置、案例和插件校验值在启动前检查；运行器改变后需新建对照计划，不静默接续旧计划。已completed的组跳过；ready可按原计划继续。attention、invalid、pending或其他不确定状态不自动重试、不自动生成替代样本；先按运行器异常流程核对。需要补跑时应另建并记录新计划，不更换原失败样本。

## 评分和比较

每个record路径由schedule.json列出；对每组使用原有命令：

```sh
python3 study.py long grade --record '<该组plan.json绝对路径>'
# 按冻结标准填写该目录scores.json，再执行：
python3 study.py long grade --record '<该组plan.json绝对路径>' --scores '<该组scores.json绝对路径>'
python3 study.py long report --record '<该组plan.json绝对路径>'
```

十个receipt项核对正式/作废状态、最新有效版本和对象归属；不能只看码是否出现在答案中。state/authority/delivery需要有原文证据的语义审阅。conclusions选择recovery实际结论正文；recall结论也逐项检查。来源是否完整按实际片段、偏移和截断判断，不按工具名称判断。未知、错误、格式问题、工具失败和协议无效分开报告。

重点分别报告10个回执的正确/未知/错误、13项完整交付结果、截断后读取是否成功，以及recovery墙钟、工具调用和版本使用情况。三个材料对是分析单位；不能将分支、阶段和条件数扩大成独立样本数。没有观察到失败不等于已经证明泛化；耗时差异也仅是探索性观察。

如需另生成未使用的材料集，用新目录执行 `python3 transfercase.py build-suite --output <新目录>`，再将三个JSON路径通过prepare的--cases传入。不要覆盖已经执行的材料，或根据目标答错的位置调整标准答案和布局。
