# 历史查回插件 0.1.1：命中片段边界修复

0.1.0 的V7运行出现过一次错码：搜索片段从目标工单前150字符开始，包含上一行末尾的另一条码值，模型将其配给目标工单。0.1.1 修正展示边界，不加入任何针对工单号、特定码值或标准答案的解析。

## 修复内容

- 搜索片段限于匹配所在的原始行，最多600个UTF-16代码单元；如果查询本身跨行，则只包含它明确跨越的行。
- 返回 match_start_char/match_end_char 标记查询的原文范围，line_start_char/line_end_char 标记行范围，start_char/end_char 标记实际返回范围，均以UTF-16代码单元计数。
- truncated 表示原始消息有内容未返回；line_truncated 表示匹配行本身仍不完整。完整命中行不等于完整消息，也不等于已验证该行内全部值的语义归属。
- 需要更多原文时，read_hint 提供当前事件seq与读取偏移。短消息完整返回时提示为null，不强制额外调用read。
- read 从非零偏移开始时，truncated 为true；has_more与next_offset只表示后方是否还有内容。读到末尾不代表已经读过前文。

工具仍只读当前会话原始用户事件，不接受其他会话ID或路径，不使用助手旧答案、摘要或外部学习。工具名称与调用参数保持一致；输出增加范围和提示字段，工具描述也同步更新。

## 限制

换行边界是通用文本边界，不是业务记录解析。同一行包含多个对象、引用或多条码值时，仍需依据标识和原文判断归属。本修复减少跨行混淆，不保证模型不再抄错，也不代表正式V7成绩已经提高。

搜索仍每条用户消息返回首个命中，按原始事件序号升序排列；最多10条。大量重复命中、语义检索与状态提取不属于本次修复。

## 版本隔离与运行

- 0.1.0：plugins/current-history，保持原文件，既有实验快照不改写。
- 0.1.1：plugins/current-history-v0.1.1，新建计划默认选择此版本。
- 可用 `--history-plugin-version 0.1.0` 重新建立旧版实验。版本选项必须与 `--history-plugin` 一起使用。
- 每次新计划仍冻结逐文件校验值；已有计划不会升级到新的默认版本。

运行器示例见[插件运行文档](current-history-plugin.md)。新版本的V7/V8.1正式对照需使用新目录，沿用冻结用例与评分，不与0.1.0运行混计。

## 验证范围

自动检查覆盖：相邻合成记录及其码值排除、匹配行原文一致性、首尾行、CRLF、Unicode偏移、长行截断、读取偏移与分页、完整短消息、明确跨行查询，以及原有会话隔离与输入限制。旧版自身的测试也继续运行，确保版本保留。

全量Python检查107项通过，其中包含两版插件的原生Node测试。真实DSH接入验证使用新的合成邻接记录，经原生压缩后实际调用search和read，返回正确凭据；search命中片段不含左右相邻记录的值。最终插件文件校验值与验证快照一致，0.1.0源码校验值保持不变。证据保存在本地 studies/history-plugin-smoke-0.1.1-2/。
