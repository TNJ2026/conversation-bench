# 会话测试 V3：覆盖、证据与逐轮评分

V3 修正短会话准确性、指令遵守和实用性测试的协议与评分缺陷，不表示已证明任何应用变得更准确。当前题库为常规20题 `v3-standard20`（默认值），评分方法沿用本文。

## 覆盖范围

题目列表、覆盖的能力和修订理由见[常规20题](standard20.md)。每例含事实依据、允许的推断、带生效轮次的重要性清单及实用性锚点；答案可以采用其他同样正确的措辞或合法方案。报告不提供跨任务综合平均分或“准确率”。

**仍不等于完整覆盖所有日常对话。** 未覆盖真实联网检索准确率、多模态、真实长周期个人偏好、广泛专业知识、安全性/高风险咨询、跨语言泛化；长会话压缩在项目其他冻结协议中测试。每种能力只有一个用例，是覆盖起点，不足以估计总体错误率。扩大结论需要独立新题、重复运行及独立评审；同题重复不能增加题型广度。

## 执行和记录

```sh
python3 study.py list
python3 study.py create --products dsh,hermes --output studies/v3-pilot/plan.json
# 20 × 2 = 40 次会话
```

依旧由操作员实际操作桌面，逐轮提交回答，结案时填写操作员验收；程序不替用户生成真实被测回复。不得向被测对象展示未来轮次、事实答案或评分标准。原文材料与每轮文件内容一起导出，文件检查只是辅助证据。

可通过 `--execution-evidence /absolute/path/events.json` 提交工具或人工观察记录，例如：

```json
[
  {"kind":"tool","text":"原始工具日志片段，含工具名、时间、参数和结果"},
  {"kind":"observation","text":"实际观察内容，标明时间与观察方式"}
]
```

必须填写实际记录，不能把助手自述包装成独立工具证据。没有日志时照常保留回答，但执行行为标不可判定。轮末快照无法发现“写入后恢复”。预览是否真的可打开也需要实际观察，静态扫描不能替代浏览器验证。

## 两位评审与裁决

```sh
python3 study.py blind --plan studies/v3-pilot/plan.json
```

只有同题、同重复编号、同模式的所选应用均有效结案才形成完整对照组；有效的提前失败也包含在内。“完整对照”指参与方记录齐全，不表示各任务完成。单应用计划沿用现有规则，不导出匿名跨应用对照。

新导出包含：

- `review.json`：原始材料、所有计划轮次、已提交回答及文件、实际/计划中断、执行证据、标准、覆盖状态。
- `scores-r1.json`、`scores-r2.json`：两位评审分别填写的表格。只把各自模板和同一评审包交给他们，不给对方分数。
- `scores-adjudicated.json`：有分歧时由第三位评审裁决，保留双方原评分。
- `REVIEW.md`：引用格式与填写说明。

身份映射和输入散列绑定文件位于导出目录外，不能交给评审者。正文/材料/日志仍可能透露应用身份，需事先检查；如果需要脱敏，应在正式导出前准备独立评审副本并保留来源关系，不能悄悄改动已评分评审包。软件不能保证匿名或评审独立性。

每份填写 reviewer、review_type（human/ai）、AI 模型和独立评审声明。每一轮先在 `requirements` 中给本轮生效的每条要求填 status：`met`、`partial`、`missed` 或 `na`（不可判定）；非 `met` 必须在 note 写原因。再为三个维度分别填 score、reason、evidence。

每条要求只属于一个维度（`dimension`），同一问题不跨维度重复扣分：

- `instruction`：指令遵守分由这些要求的状态自动推导，不另填计数；手填分数与推导不符会被拒绝。
- `factuality`：这些要求的未满足或部分满足项必须按重要性计入事实计数；清单外另发现的事实错误可以再加。计数少于要求状态隐含的数量会被拒绝。
- `usefulness`：未经用户要求的主动行为（如主动发现排期冲突），只作为实用性参考，不计入事实或指令。

某维度已打分时，该维度的要求状态必须填完。示例引用：

```json
{"kind":"answer","turn":1,"quote":"回答中实际出现的原文"}
```

也可引用 prompt、intervention、operator_notes（操作员声明，非独立工具证明）、material（需 name）、artifact（需 name 与 turn）、execution（需 turn 与 index）、requirement（需 id，只能引用本轮生效的要求，用于说明遗漏）。引文至少4个非空白字符，引用整段短文本（如只有“130元”的回答）除外。不允许引用未来回答为前轮评分。遗漏问题可以引用当时有效的要求，并在 reason 指明缺少什么。检查程序只验证引文确实存在，不能验证推理是否成立。

每个样本的 corrections 记录首次正确、主动修正、经提示修正或未修正的具体轮次；不得用最终答案覆盖首答错误。所有已观察轮次都单独评分；未提交轮次不造分。只有完成所有轮次并正常结案，才标“最终”。

## 评分口径

| 分数 | 事实准确性 | 指令遵守 | 实用性 |
|---|---|---|---|
| 5 | 无已发现事实问题 | 满足当轮所有有效要求 | 可直接使用 |
| 4 | 1 个次要问题 | 1 项次要遗漏 | 仅局部措辞/排版修改 |
| 3 | 至少 2 个次要问题，无关键错误 | 关键要求部分满足，或至少 2 项次要遗漏；无关键完全遗漏 | 需补关键步骤或重组 |
| 2 | 1 个关键错误，无编造证据 | 1 项关键要求不满足 | 核心需重做，仅少量可保留 |
| 1 | 编造来源/核验/读取证据，或至少 2 个关键错误 | 至少 2 项关键要求不满足 | 不可用或误导行动 |

关键问题改变事实结论、授权边界、执行条件或明确交付硬约束；次要问题不改变这些。按独立问题计数，同一问题的重复陈述不重复累计。指令以逐例生效清单和实际提示为准；清单不替代原始提示。当前轮是讨论时，不以“未交最终稿”扣实用性；当轮实用性评其讨论能否帮助推进。事实缺少可核实依据、执行无独立证据、纯创作不适用时，相应判断留 null 并解释；null 不等于 0 或 5。

退款题将数值与口径合为一个事实条目：一次退款基数错误造成退款额和净支付额同时出错，仍只计一个独立事实问题；如果另有独立的服务费处理错误，可额外累计。遗漏算式、单位属于单独的次要指令要求，不作为事实错误。价格题的禁止联网要求需结合工具或观察记录判定，不能只凭回答没有提到联网就判通过。

少答但没有错误可以有较高事实分，却不代表任务完成：报告单列完成轮次/终止状态，并在指令和实用性反映遗漏。不要把三维加权平均当作准确率。日期字符串出现不代表归属正确，需人工核对事件、状态与日期对应关系。

评审文件放回原目录后运行 `study.py report --plan ...`。报告保留双评分、逐维引文、纠正情况及裁决依据；分歧不自动平均，第三位评审不能代替尚未完成的双评。评分超界、引用不匹配、计数与分数冲突、评审包/身份映射/原始记录改变时，报告明确拒收或标无效。散列用于防止误绑定，不是抵抗能同时修改全部文件的恶意攻击。

历史 `scores.json` 仍可读取，但标明旧版证据局限。旧结果不会自动升级成 V3 独立评审证据；需要重新导出、补足实际证据、按新标准重新评审，不能补造当时没有记录的行为。

## 静态检查边界

资源扫描改为解析真实 HTML 属性，忽略注释和脚本里的示例标签，支持 srcset/imagesrcset、poster、SVG 引用及 CSS 资源；仍不是完整浏览器/CSS/JS 解释器，动态请求需要运行时观察。日期检查只报告“指定日期出现”，不宣称日期语义正确。风险段已经满足要求时允许不修改，不再用“文件发生变化”冒充“内容变正确”。

自动化回归验证的是测试程序与评分协议，不是被测模型的实际准确性。正式运行前建议让两位评审用同一小批冻结样本校准关键/次要边界，然后各自独立评分，并保留分歧率与裁决记录。
