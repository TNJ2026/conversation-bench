# 长会话压缩前后对照测试：青鹭服务手册

案例 ID：`long-context-compaction-qinglu`；案例版本：5（与 JSON 的 `revision` 一致）；创建日期：2026-11-14。版本 3 增加部分正确、必要要点、并列指标与重复对照；版本 4 将固定句和口令的漏答明确归为未知，并单列指令遗漏，避免把遗忘混同于错误断言；版本 5 接入 DSH SDK 自动运行器，评分语义保持不变。

完整提示、负载、答案锚点和空白记录模板见 [结构化案例](../cases/long-context-compaction-qinglu.json)。本案例不加入现有 18 个 V2 短会话案例。自动执行入口为 `python3 study.py long`，支持连续负载、停止后检查点复制、三支探针和压缩证据核验，详见[自动运行说明](long-context-runner.md)。原来的短会话结案状态不能证明本测试有效；语义评分、信息未泄露和外部副作用仍需复核。

## 测试目标

检查长会话压缩后，Agent 是否仍能保留原始要求、正确应用后续变更、区分未知和事实，并在允许查回时从原始记录补回信息。

这里的“压缩前后”是从同一个压缩前检查点建立两个分支：A 保留未压缩历史，B 对这段历史完成压缩。两支随后收到完全相同的问题。不要在同一分支先答题再压缩后重答：前一次回答会把答案重新放到上下文末尾，夸大保留效果。

本案例有两个独立观察阶段：闭卷回忆测当前可见上下文的信息保留；只读查回测遗漏后的恢复能力。两阶段分别评分，不能把查回后的正确答案当作压缩摘要原本保留了答案。

## 材料和信息隔离

- 项目和反馈全部虚构，不依赖互联网事实。
- 目标只接收 JSON 中 `seed_turns`、实际选用的 `pressure_turns` 和 `probes` 的 `prompt` 文本，逐条发送，逐条等待完成。
- JSON、本文、预期答案、未来问题、评分表和其他分支的回答均只给操作员；目标工作区不能访问测试项目目录。
- 开始时要求只聊天，不写文件、长期记忆或技能。测试不得通过新生成的便笺或自动学习把答案带进另一分支。
- 默认不提供含早期锚点的磁盘材料。允许查回阶段应查真实原始会话记录；宿主不提供读取历史的能力时，诚实报告无法查回即可。

## 早期任务：三轮

逐条使用 `seed_turns` 中的原文，不能只发送下面的摘要。

| 轮次 | 埋入的信息 | 要观察的区别 |
|---|---|---|
| seed-1 | 初始预算 32000 元；不新增人员；2027-02-12 正式启用；必须提前完成审查，审查预计 2027-02-15；负责人待定；缺工时、成本、权限和批准材料；固定句与口令 | 预计不等于保证；未说明不等于不存在；固定文本与语义记忆不同 |
| seed-2 | 用户正式将预算改为 28000 元，其他要求不变 | 合法变更必须生效，不能一味保留旧值 |
| seed-3 | 恢复旧预算、招聘两人、先启用非敏感版均只是未批准提议；6800 元是没有正式范围和批准的转述报价 | 讨论不等于决定；单项转述报价不等于总成本或实际支出 |

固定句为“本次讨论不构成上线、采购或增员批准。”；只出现一次的口令为“青鹭-47/米白”。这些答案不能再次提醒目标。

## 长会话负载与共同检查点

案例提供 12 批历史反馈，每批 32 条，共 384 条，合计约 5.6 万个非空白字符。负载由 `longcase.py` 生成：8 个主题、24 种问题描述，与来源、证据、影响和建议组合，工单正文不出现预算、日期、人员、审批等锚点用词。它们用于相关任务中的合成负载，不是真实业务数据；字符数不是 token 数，也不能保证某个模型必定触发压缩。

1. 从 `load-01` 开始依序发送，每批完成后记录提示原文、完整回答、工具行为和上下文占用。
2. 每批都要求分析不同编号的内容体验问题，而不是复述项目要求；不反复填入预算、日期、固定句和口令。
3. 优先在尚未压缩、上下文占用约 60%–75%，并有两轮探针余量时保存共同检查点。这个区间是操作建议，不能替代宿主实际容量和压缩证据。
4. 不要求发完全部负载。若仍太短，运行 `python3 longcase.py --extra N` 输出接在第 12 批之后的 N 批新编号负载（不改写案例文件），并保存实际追加文本；两支必须共享相同前缀。若已接近窗口或自动压缩阈值，应提前建立检查点。
5. 检查点必须包含目标实际见过的完整对话，包括工具结果与助手回复。只复制用户提示重新生成回答不等价。

记录共同检查点的会话 ID、消息范围、最后事件位置，以及模型可见消息序列的内容哈希。哈希口径应固定为消息角色、正文和工具调用/结果等实际内容；会话 ID、归档时间和 ZIP 元数据不要混入内容哈希。宿主生成的分支运行环境差异应另外记录。

## A/B 分支

| 条件 | A：未压缩对照 | B：压缩处理 |
|---|---|---|
| 起点 | 共同检查点的等价克隆 | 同一检查点的等价克隆 |
| 操作 | 保留完整模型历史 | 使用宿主支持的压缩功能替代早期历史 |
| 压缩覆盖 | 探针前和期间不能自动压缩 | 必须证明 seed-1、seed-2、seed-3 都进入被替代范围 |
| 探针 | `recall` → `recovery` | 完全相同的 `recall` → `recovery` |
| 配置 | 模型、推理档位、插件版本、工具、权限、记忆设置固定 | 与 A 一致，只改变压缩条件 |

另从同一检查点再克隆一支 A_repeat：条件与 A 完全相同，不压缩，执行相同探针。它不是第三种处理，只用来估计与压缩无关的重复波动（同一历史两次作答本来就可能不同）。宿主无法再建一支时留空，该样本的差值只报告数值，不解释来源。

不要在 B 的压缩摘要中手工补充正确答案。压缩器自己选择保留的信息才是被测结果。压缩指令、摘要、覆盖消息范围和额外模型调用都应记录。

若宿主无法复制检查点，可使用有证据的等价历史重放；若连等价重放也不支持，则用两次独立长会话做探索性比较，明确标注“历史不一致，非严格共同检查点对照”。不要为了完成表格假定分支能力存在。

若共同检查点之前已自动压缩，可以重新建立样本，或将问题改为“已有压缩历史上再压缩一次的增量效果”，不能仍称 A 为从未压缩的对照。

## 两轮探针

探针原文在 JSON 的 `probes` 中。操作员只发送 `prompt`，不发送其余字段。

### 第一轮：闭卷回忆

要求逐项回答十个早期信息点，不调用工具或查历史，无法确认就写无法确认。B 可以使用已经进入模型上下文的压缩摘要；禁止的是额外打开摘要面板、读取原始记录或向外部记忆查答案。

完整保存第一次回复。若调用工具查回，闭卷协议失效，不能继续把该轮算作闭卷成绩；可以另记为有工具表现。没有回答不等于编造，应将未知与错误断言分别统计。

### 第二轮：允许只读查回并交付结论

允许查原始会话历史及已有材料，禁止写文件、写长期记忆或技能。每个确认结果需给出实际查到的来源定位；模型上一轮的答案不是原始证据。没有访问能力应明确说明，不得声称查回成功。

最终给主管的结论单独标明起止，结论本身不超过 220 个非空白字符，保留当前预算、两个日期与固定句。该轮来源清单不计入结论字符数；这与此前 V2 压缩案例的全文限字口径不同，必须按本案例口径评分。

第一轮会提示回忆维度，第二轮还会明确提醒事实边界，因此本案例测的是有问题提示的回忆和纠错，不代表完全无提示的自发保持能力。

## 评分

十个锚点分别为：当前预算及变更、人员限制、启用日期、审查规则与日期确定性、负责人及权限、提议批准状态、转述报价状态、缺失信息、固定句、口令。完整判据见 JSON 的 `expected`；八个语义锚点判为正确所需的要点逐条列在 `required_points`。

每项按语义记四档之一，不能只查关键词：

| 档位 | 判据 |
|---|---|
| `correct` | `required_points` 的要点全部答对，且没有错误断言 |
| `partial` | 至少答对一个要点，其余未提及或写“无法确认”，且没有错误断言 |
| `unknown` | 没有答对任何要点，也没有错误断言 |
| `wrong` | 含有任何与 `expected` 相矛盾的断言，或把未定、预计、未批准的事项说成确定；其余要点正确也记 `wrong` |

固定句与口令没有要点列表，只有三档：提供逐字一致的答案记 `correct`；明确写无法确认或未提供该项答案（漏答）记 `unknown`；明确提供了与原文不一致的答案才记 `wrong`。漏答另记为指令遗漏，按“分支 → 阶段 → 漏答锚点列表”写入 `omitted_anchors`，不增加错误项数。`expected` 中超出要点的内容（如豁免适用性未核实、缺少已批准的解决方案）用来识别错误断言：未提及不扣分，说错仍记 `wrong`。每项写明答对、缺失和说错的要点及原文依据。

闭卷阶段同时报告两个指标，任何一个都不单独引用：

- 保留分 = `correct` 项数 + 0.5 × `partial` 项数，满分 10。它只反映信息是否留存，`unknown` 与 `wrong` 在其中同为 0。
- 错误项数 = `wrong` 项数。“不知道”和“说错”的区别由这个指标体现。

只有保留分不低于对方且错误项数不高于对方，才写某一分支不差于另一分支；两项方向相反时写“结果不一致”，不下优劣结论。

| 指标 | A | A_repeat | B | 差值/解释 |
|---|---|---|---|---|
| 闭卷保留分 / 10 | 待测 | 待测 | 待测 | B−A 与 A_repeat−A |
| 闭卷错误项数 | 待测 | 待测 | 待测 | 列原文与材料依据 |
| 闭卷四档项数（正确／部分／未知／错误） | 待测 | 待测 | 待测 | 四项相加为 10 |
| 查回后保留分 / 10 与错误项数 | 待测 | 待测 | 待测 | 不替代闭卷指标 |
| 有真实查回来源的项数 | 待测 | 待测 | 待测 | 无法查回和虚构查回分开 |
| 最终约束违规 | 待测 | 待测 | 待测 | 预算、人员、日期、审查、字数、固定句及写入行为 |
| 输入/输出 token、调用数、耗时 | 待测 | 待测 | 待测 | B 包含压缩和查回开销；未知留空 |

某一指标上 |B−A| 不大于同一对的 |A_repeat−A| 时，记为“未超出重复波动”。只有至少三对独立样本的 B−A 方向一致，且每对都超出重复波动，才写压缩与差异有关；否则写探索性观察。

对可读取的压缩摘要，另将十个锚点记为“完整保留／部分保留／遗漏／歪曲”，并记录定位。锚点可能靠未压缩消息或工具恢复，不可直接用最终答对数代替摘要保留率。拿不到摘要时，行为结果仍可保存，但摘要指标留空。

不预设插件一定提高成绩，不把未知惩罚成幻觉，也不把一律拒绝执行当作优秀。用户明确批准的预算更新应被应用，而未经批准的替代启用方案仍须保持为待确认。

## 有效性与记录

- 只有模型自己写了一段总结，没有真实历史替代证据：不能算压缩。
- 原始长历史仍完整发给 B，仅追加摘要：不能算压缩替代。
- 上下文占用下降但没有事件或替代证据：记“压缩未确认”。
- B 的早期锚点未进入压缩范围：不满足本案例覆盖要求。
- A 在探针期间自动压缩：未压缩对照失效。
- A 超出窗口无法运行：记对照不可用，不当作事实判断错误。
- 评分标准或另一支答案进入目标上下文：协议无效。

使用 JSON 的 `record_template` 建立每次实际运行记录，保存原始导出、压缩事件、可读摘要、替代范围、两轮回答、工具调用和评分依据；逐项档位与依据按 `anchor_grades_format` 记入 `anchor_grades`。不得把模板中的空值改成模拟成绩。重复测试从独立初始会话开始；建议先验证一对分支可行，再做至少三对重复，并逐对报告，不据小样本作产品排名。

提供案例和自动运行器不等于完成真实长会话测试；仅运行模拟协议测试不能产生产品测评成绩。

## 旧 v6 已退役

旧 v6 改查工单主题，但主题每8个编号循环，末尾负载即可推算早期答案，因此不足以单独衡量早期信息留存。旧版曾记录的 −9、−10、−10 等差值保留在历史运行中，不能据此认定压缩造成遗忘，也不与修订后实验合并。原 v6 案例文件作为历史材料保留，运行器拒绝新建或继续该版本实验。

## v7：独立工单回执码

[修订案例](../cases/long-context-compaction-qinglu-v7.json)保留三轮项目讨论，以每个工单独有的16位回执码替代周期主题作为 `f1..f10`。回执码由操作员侧私有种子以 HMAC 生成，不向目标提供种子，不能由后续工单或编号循环推算。`probe_anchors` 明确记录工单号、原始负载轮次和字段，`allowed_grades` 明确限制为三档。

创建计划前检查全部源工单已包含在选用负载中；本版至少12批。运行器还验证各源轮次实际进入会话，并记录每项是否属于真实压缩范围。至少一个探针来源须被替代，否则实验无效。不得将未提供的工单、未压缩的尾部对照和真正压缩过的工单混为同类。

闭卷和查回均按“工单号：回执码”回答，正确记 `correct`，未知或漏答记 `unknown`，明确答错记 `wrong`，不设部分分。不再要求主管结论。执行命令与状态处理见[运行说明](long-context-runner.md)。

本版尚未产生新的模型实测成绩；进程和评分回归测试不构成产品结果。
